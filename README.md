# witden

**可自托管的开源 AI 员工平台：在控制台配置角色和虚拟电脑，让它们作为机器人在 Slack、飞书、GitHub 中工作。**

witden 让你拥有一组“AI 员工”。每位 AI 员工（称为**角色**）有自己的身份、职责、提示词和模型，在分配给它的**虚拟电脑**里执行命令、读写文件、操作桌面和浏览器。

管理员在网页控制台中配置角色和虚拟电脑，也可以直接在控制台里和角色对话。角色还可以作为 Slack、飞书、GitHub 的机器人工作，为那里的成员、群和仓库服务：它像一个真实的同事，同时处理多个群和多个人的会话，而不是某一个人的私人助手。控制台就像这些机器人自己的通讯软件，它们在各处的会话都汇集在这里。

## 核心概念

| 概念 | 说明 |
|---|---|
| 虚拟电脑 | 基于 Docker 的隔离环境，从模板创建，可以是命令行环境或带图形桌面和浏览器的环境。角色的所有操作都只发生在虚拟电脑内。 |
| 角色 | AI 员工。配置名称、头像、职责、提示词、模型、所在的虚拟电脑和工具权限。 |
| 话题 | 一段会话：控制台里围绕一件事情的协作，Slack、飞书中的一个 thread 或一段私信，或 GitHub 上的一个 issue 或 pull request。控制台里还有私信：管理员与某个角色之间一直保留的一对一对话。 |
| 管理员与外部成员 | 能登录控制台的账号都是管理员，可以看到全部会话。Slack、飞书中未关联到管理员账号的人，可以作为外部成员使用连接允许的角色，彼此的私信相互隔离。 |
| 任务 | 角色接到的一项工作。任务记录请求人、执行过程、所用的虚拟电脑和结果，可以暂停、补充要求、转交或取消。 |
| 审批 | 需要人工确认的操作，以及需要资料所有者同意才能公开的内容。 |

## 主要功能

**会话**
- 控制台汇集角色的全部会话，按来源分组：控制台里的话题与私信，Slack、飞书中的 thread 和私信，GitHub 上的 issue 和 pull request；所有管理员都可以查看，加入话题的角色可以阅读全部历史。
- 角色响应方式按话题设置：“主动 @”（默认）只在角色被 @ 时响应；“自动”模式下，没有 @ 的消息也可以由角色处理——只有一个角色时由它判断是否需要回复，有多个角色时由调度模型决定交给哪些角色。
- 消息支持 Markdown、图片和 Mermaid 流程图；角色工作时实时显示思考状态、正在使用的工具和逐字生成的回答。
- 接入 Slack（飞书为实验性支持）：一个 thread 对应一个话题，消息格式自动转换。
- 接入 GitHub（GitHub App 或机器人账号）：在 issue 或 pull request 中 @ 机器人即可让角色工作，回复以评论发回；公开仓库中的内部资料需要批准才会发出。

**虚拟电脑**
- 版本化模板，从模板创建多个独立实例；支持启动、停止、重启、重置、删除、备份、恢复和复制，复制时默认不带账号凭据。
- 在网页中实时观看桌面；管理员可以接管鼠标和键盘，接管期间这台虚拟电脑上的 AI 工作暂停，离开或长时间不操作时自动交还。
- 可选的模型访问：虚拟电脑里的程序可以通过平台使用已配置的模型，真实的服务地址和密钥不会进入虚拟电脑。

**安全与治理**
- 能登录控制台的只有管理员；Slack、飞书中未关联的人默认不能使用角色，开启后作为外部成员只能使用连接允许的角色，并且不能登录控制台。
- 工具权限分为“始终允许 / 询问 / 禁用”。新角色默认：在自己虚拟电脑里的操作始终允许，联系其他角色、使用平台记忆和读取其他话题需要询问。
- 内容发往 Slack、飞书之前检查信息流向：一个人的私信或其他会话中的资料，不会出现在无权看到它的人面前，除非资料来源的管理员批准。
- AI 的操作只能进入任务所在的那台虚拟电脑，从不在服务器上直接执行；虚拟电脑不可用时任务等待或失败，不会改用其他机器。
- 紧急停止即时生效；所有关键操作记录审计。

**模型**
- 按“服务商 → 模型”管理：对话模型支持 OpenAI 兼容接口（如 vLLM、Ollama、DeepSeek）和 Anthropic 接口；模型可以从服务商获取列表后选择，也可以手动填写。
- 可检测模型的对话、工具调用和图像理解能力以及响应时间；按角色和模型设置每日 token 额度，并统计用量。
- 支持 System 1 决策模型（System One 接口）：TypeSafe Jev 和开源的 Laya。它们针对给定内容回答选择题并给出概率，响应快，用作话题调度模型；Laya 可以作为 Docker Compose 的可选服务一起部署。

## 系统组成

witden 采用“外部编排、内部执行”的设计：平台负责身份、话题、权限、任务和模型调用；每台虚拟电脑里运行一个执行代理（Runner），负责真正的命令、文件、屏幕、键鼠和浏览器操作；只有独立的 Docker Manager 服务能够管理容器。详见[系统架构](docs/architecture.md)。

```
Slack / 飞书 / 网页控制台
          │
          ▼
   API 服务 ───────► Docker Manager ───► Docker（虚拟电脑容器）
     │   ▲                                        │
     │   └──────────── 执行代理（Runner）连接 ◄────┘
     ▼
 PostgreSQL ◄─── Worker（运行 AI 角色、调用模型）
```

## 快速开始

以下步骤在一台机器上以单进程方式运行 witden，适合试用和开发。需要 Node.js 22 或更高版本以及 Docker；数据库默认使用内置的嵌入式 PostgreSQL，无需另外安装。

```bash
npm ci
make images            # 构建虚拟电脑镜像
npm run build          # 编译平台与网页控制台
export WITDEN_BOOTSTRAP_ADMIN_EMAIL=admin@example.com
export WITDEN_BOOTSTRAP_ADMIN_PASSWORD=change-me-please
node packages/server/dist/cli.js serve
```

启动后访问 <http://localhost:8320>，用上面设置的管理员账号登录，然后按顺序完成：

1. **模型**：添加服务商，获取或填写模型，并点击“检测能力”。
2. **虚拟电脑**：在“模板”中点击“导入内置模板”，再从模板创建虚拟电脑，等待其状态变为运行中。
3. **角色管理**：创建角色，选择模型和虚拟电脑。
4. **话题**：在左侧点击角色与它私信，或新建话题并邀请角色，在输入框中输入 @ 并选择角色，开始工作。
5. **通讯接入**（可选）：接入 Slack，让角色作为机器人在 Slack 中工作，参见[接入 Slack](docs/slack.md)。

团队部署请使用 Docker Compose，参见[部署与配置](docs/deployment.md)。
