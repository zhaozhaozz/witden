# witden

**可自托管的开源 AI 员工平台：在控制台配置角色和虚拟电脑，让它们作为机器人在 Slack、飞书、GitHub 中工作。**

witden 让你拥有一组“AI 员工”。每位 AI 员工（称为**角色**）有自己的身份、职责、提示词和模型，在分配给它的**虚拟电脑**里执行命令、读写文件、操作桌面和浏览器。

管理员在网页控制台中配置角色和虚拟电脑，也可以直接在控制台里和角色对话。角色还可以作为 Slack、飞书、GitHub 的机器人工作，为那里的成员、群和仓库服务：它像一个真实的同事，同时处理多个群和多个人的会话，而不是某一个人的私人助手。控制台就像这些机器人自己的通讯软件，它们在各处的会话都汇集在这里。

## 核心概念

| 概念 | 说明 |
|---|---|
| 虚拟电脑 | 基于 Docker 的隔离环境，从模板创建，可以是命令行环境或带图形桌面和浏览器的环境。角色的所有操作都只发生在虚拟电脑内。 |
| 角色 | AI 员工。配置名称、头像、职责、提示词、模型、所在的虚拟电脑和工具权限。内置的系统管理员（@admin）始终存在，只在控制台中工作，负责 witden 自身的配置。 |
| 话题 | 一段会话：控制台里围绕一件事情的协作，一个 Slack 频道（其中的 thread 显示为回复）、一个飞书群聊（其中的消息串显示为回复）或一段私信，或 GitHub 上的一个 issue 或 pull request。控制台里还有私信：管理员与某个角色之间一直保留的一对一对话。 |
| 管理员与外部成员 | 能登录控制台的账号都是管理员，可以看到全部会话。Slack、飞书中未关联到管理员账号的人，可以作为外部成员使用接入的机器人代表的角色，彼此的私信相互隔离。 |
| 对话 | 角色在每个话题、每个私信里各有一段对话：上下文从一条消息延续到下一条，不同话题之间互不相通。角色工作时收到的新消息会在它的下一步交给它；对话变长时，角色把前面的内容整理成摘要继续工作。 |
| 记忆 | 角色需要长期保留的内容，按适用范围分为两种：话题记忆只在一个话题或私信中使用，角色记忆属于角色本身、在它工作的所有地方都适用。管理员还可以在知识空间中维护团队知识供角色检索。 |
| 任务 | 角色单独开展的一项工作：从对话中拆出的较大工作，或委托给其他角色的工作，有自己的上下文，完成后结果回到对话。任务记录请求人、执行过程、所用的虚拟电脑和结果，可以暂停、补充要求、转交或取消。 |
| 审批 | 需要人工确认的操作，以及需要资料所有者同意才能公开的内容。 |

## 主要功能

**会话**
- 控制台汇集角色的全部会话，按来源分组：控制台里的话题与私信，Slack 频道、飞书群聊和私信，GitHub 上的 issue 和 pull request；所有管理员都可以查看，加入话题的角色可以阅读全部历史。
- 角色响应方式按话题设置：“主动 @”（默认）只在角色被 @ 时响应；“自动”模式下，没有 @ 的消息也可以由角色处理——只有一个角色时由它判断是否需要回复，有多个角色时由调度模型决定交给哪些角色。
- 消息支持 Markdown、图片和 Mermaid 流程图；角色工作时实时显示思考状态、正在使用的工具和逐字生成的回答。
- 接入 Slack（飞书为实验性支持）：一个频道对应一个话题，和 Slack 中看到的一致，thread 中的消息显示为回复；角色在提问的地方回答，也可以像人一样连续发几条消息。消息格式自动转换。Slack、GitHub、飞书都由控制台按步骤引导设置（GitHub App 一键创建）。Slack 默认使用 Socket Mode、飞书默认使用长连接，都由 witden 主动连到平台，不需要公网地址。角色还可以经 witden 受控地使用飞书的日历、文档与知识库、多维表格、电子表格、视频会议和任务，按公司和功能授权，飞书应用的凭据不交给角色。接入 GitHub 等需要公网地址时，公网只开放单独的事件端口，控制台留在内网；没有公网 IP 时，可以使用 Docker Compose 中可选的 Cloudflare Tunnel 服务。
- 接入 GitHub（GitHub App 或机器人账号）：在 issue 或 pull request 中 @ 机器人即可让角色工作，回复以评论发回；公开仓库中的内部资料需要批准才会发出。角色还可以经 witden 以接入的账号或 App 的身份读代码、处理 issue 和 pull request、查看和触发 Actions，按接入和类别授权；只想让角色代替某个人操作时，可以把这个人的账号设为“只作为认证”，不当机器人使用。

**虚拟电脑**
- 版本化模板，从模板创建多个独立实例；支持启动、停止、重启、重置、删除、备份、恢复和复制，复制时默认不带账号凭据。
- 在网页中实时观看桌面；管理员可以接管鼠标和键盘，接管期间这台虚拟电脑上的 AI 工作暂停，离开或长时间不操作时自动交还。
- 可选的模型访问：虚拟电脑里的程序可以通过平台使用已配置的模型，真实的服务地址和密钥不会进入虚拟电脑。

**安全与治理**
- 能登录控制台的只有管理员；Slack、飞书中未关联的人默认不能使用角色，开启后作为外部成员只能使用接入的机器人代表的角色，并且不能登录控制台。
- 内置的系统管理员（@admin，始终存在，不能停用或另外添加）：在控制台中通过对话完成 witden 的配置（角色、模型、虚拟电脑、通讯接入、知识；账号只由人管理），以提问的管理员身份操作并记入审计；它不处理 Slack、飞书、GitHub 的消息，其他角色也不能把工作交给它。
- 密钥在任何地方都读不出来：模型 API Key、通讯接入凭据、Tunnel token、虚拟电脑的模型访问密钥只能由人在控制台中填写或更换，界面和接口只显示是否已设置，系统管理员角色也读不到、改不了。
- 工具权限分为“始终允许 / 询问 / 禁用”。新角色默认：在自己虚拟电脑里的操作始终允许，联系其他角色、使用平台记忆和修改自己的职责说明需要询问，读取其他话题禁用。开启“读取其他话题”的角色可以在多个渠道之间协调，例如在飞书中处理 GitHub 上的事情；私信始终只属于它的人和角色，不能从其他话题读取。
- 角色能读取哪些资料由它的权限决定（知识空间、飞书和 GitHub 工具、读取其他话题）：有权读取的内容，角色可以在它工作的任何地方使用，包括发到 Slack、飞书和 GitHub。需要限制时，收窄角色的权限，或把相应工具设为“询问”。
- AI 的操作只能进入角色所在的那台虚拟电脑，从不在服务器上直接执行；虚拟电脑不可用时工作等待或失败，不会改用其他机器。
- 紧急停止即时生效；所有关键操作记录审计。

**模型**
- 按“服务商 → 模型”管理：对话模型支持 OpenAI 兼容接口（如 vLLM、Ollama、DeepSeek）和 Anthropic 接口；模型可以从服务商获取列表后选择，也可以手动填写。
- 可检测模型的对话、工具调用和图像理解能力以及响应时间；按角色和模型设置每日 token 额度，并统计用量。
- 添加模型服务时可以直接选择常见服务（OpenAI、Anthropic、DeepSeek、通义千问、Kimi、智谱、OpenRouter 等），只需填写 API Key；首次使用引导与模型页使用同一套界面。
- 角色可以设置思考程度（effort）：模型服务报告了某个模型支持的等级时（如 Anthropic、DeepSeek、OpenRouter），只列出这些等级；服务不报告时，使用 witden 内置的已知模型表，或列出常见等级。各种接口按自己的参数发送；DeepSeek 等返回的思考内容会在后续请求中带回。
- 支持 System 1 决策模型（System One 接口）：TypeSafe Jev 和开源的 Laya。它们针对给定内容回答选择题并给出概率，响应快，用作话题调度模型；Laya 可以作为 Docker Compose 的可选服务一起部署。

## 系统组成

witden 采用“外部编排、内部执行”的设计：平台负责身份、话题、权限、任务和模型调用；每台虚拟电脑里运行一个执行代理（Runner），负责真正的命令、文件、屏幕、键鼠和浏览器操作；只有独立的 Docker Manager 服务能够管理容器。详见[系统架构](docs/architecture.md)。

```
Slack / 飞书 / 网页控制台
          │
          ▼
   API 服务 ───────► Docker Manager ───► Docker（虚拟电脑容器）
     │   ▲                                        │
     │   └──────────── 执行代理（Runner）连接 ◄────┘
     ▼
 PostgreSQL ◄─── Worker（运行 AI 角色、调用模型）
```

## 快速开始

以下步骤在一台机器上以单进程方式运行 witden，适合试用和开发。需要 Node.js 22 或更高版本以及 Docker；数据库默认使用内置的嵌入式 PostgreSQL，无需另外安装。

```bash
npm ci
make images            # 构建虚拟电脑镜像
npm run build          # 编译平台与网页控制台
export WITDEN_BOOTSTRAP_ADMIN_EMAIL=admin@example.com
export WITDEN_BOOTSTRAP_ADMIN_PASSWORD=change-me-please
node packages/server/dist/cli.js serve
```

启动后访问 <http://localhost:8320>，用上面设置的管理员账号登录。第一次登录时，控制台会打开“欢迎使用 witden”引导：

1. **连接模型服务**：选择 OpenAI、Anthropic、DeepSeek、通义千问、Kimi、智谱、OpenRouter 或其他兼容服务，填写 API Key。
2. **选择模型**：从服务返回的列表中选择，或直接填写模型名称。witden 会检测模型能否对话、调用工具和理解图片。
3. **开始使用**：witden 自动创建一台桌面虚拟电脑和一个在这台电脑上工作的助手（@assistant），内置的系统管理员（@admin）还没有模型时也使用这个模型，然后打开与助手的私信。

之后可以：

- 在私信中让助手查资料、操作网页、整理文档；让系统管理员按你的要求添加角色、虚拟电脑或修改配置。
- 在“设置”中手动配置模型、虚拟电脑和角色，或新建话题并邀请角色协作。
- 接入 Slack，让角色作为机器人在 Slack 中工作，参见[接入 Slack](docs/slack.md)。

团队部署请使用 Docker Compose，参见[部署与配置](docs/deployment.md)。
