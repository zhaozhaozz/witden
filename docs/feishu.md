# 接入飞书（实验性）

接入后，角色可以作为机器人在飞书中工作：在群里 @ 机器人或私聊它，就能把工作交给 witden 中的角色。一个群聊对应 witden 中的一个会话，标题是群名，和飞书中看到的一致；消息串（回复）中的消息显示为对第一条消息的回复。角色在提问的地方回答：直接在群里提问的，回复发在群里；在消息串中提问的，回复发在这个消息串中。与机器人的私聊是一个会话。飞书接入目前为实验性，只同步文字（包括富文本和卡片中的文字），不同步图片、文件、消息的编辑和撤回。

配置需要 witden 管理员账号，以及飞书企业的应用开发权限（发布应用时可能需要企业管理员审核）。witden 目前只支持飞书（open.feishu.cn），不支持 Lark 国际版。

## 1. 接收消息的两种方式

| 方式 | 说明 | 需要的凭据 |
|---|---|---|
| **长连接**（默认，推荐） | witden 用应用的凭据主动连到飞书，通过这条连接接收消息。不需要公网地址，witden 在公网上什么都不暴露；witden 服务器能访问 open.feishu.cn 即可。 | App ID、App Secret |
| **事件地址**（HTTP） | 飞书把消息推送到 witden 的公网事件地址（只通往事件端口，不开放控制台），准备方法见[部署与配置](deployment.md#24-公网事件地址)。 | App ID、App Secret、Verification Token |

长连接只支持企业自建应用，这也是本文创建的应用类型。使用长连接时请注意：

- **一个飞书应用只接到一个 witden。** 飞书把每条消息只交给这个应用的一个连接。同一个应用同时接到两个 witden（例如正式环境和测试环境）时，消息会被随机分给其中一个，另一个就收不到。同一个 witden 的多个 API 进程不受影响，它们共用一个数据库，每条消息只处理一次。
- 每个应用最多可以有 50 个长连接。
- witden 收到消息后先保存再答复飞书；保存失败时飞书会重新推送，重复推送的同一条消息只处理一次。

## 2. 用设置引导接入

在“设置 → 通讯接入”中点击“新建接入”，选择 **飞书**，在引导开头选择接收消息的方式，按页面中的步骤完成。中途离开后，可以在接入详情中点击“设置引导”继续。

### 2.1 长连接（6 步）

1. **在飞书开放平台创建应用。** 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用（名称就是机器人在飞书中显示的名字），在“添加应用能力”中添加 **机器人**，按 2.3 节申请权限并设置通讯录权限范围。先不要配置事件订阅。
2. **填写凭据并测试连接。** 填写 App ID（`cli_` 加 16 位字母数字）和 App Secret，都在“凭证与基础信息”页面。witden 加密保存它们，之后不能再查看，并立即用它们连接飞书。测试会读取机器人的信息；应用发布之前飞书不提供机器人信息，这时页面会说明原因，可以先继续下一步。
3. **订阅消息事件。** 页面显示“与飞书的连接”，每 3 秒刷新。显示“已连接”后，在“事件与回调 → 事件配置”中把订阅方式设为 **使用长连接接收事件** 并保存：飞书只有在 witden 连上之后才允许保存。然后添加事件 **接收消息 v2.0**（`im.message.receive_v1`）。witden 收到第一个事件后，页面会提示。
4. **发布应用版本。** 在“版本管理与发布”中创建版本，在可用范围中选择能使用机器人的成员或部门，申请线上发布；需要审核时等企业管理员通过。开通的权限、机器人能力和事件订阅在发布后才生效，之后每次修改也要再发布一个新版本。发布后在这一步测试连接。
5. **选择机器人代表的角色**，以及是否允许未关联的人使用，见[接入 Slack](slack.md#3-选择机器人代表的角色)。
6. **在飞书中试一试。** 在群设置的“群机器人”中添加这个应用，在群里 @ 机器人，或直接私聊它；页面显示 witden 收到的消息和处理结果。

“与飞书的连接”一直显示“正在连接”或“连接失败”时，页面会写明飞书给出的原因，常见的有：App ID 或 App Secret 不正确；应用的长连接数已达上限；witden 服务器连不上飞书（检查网络或代理）。App ID 不存在时，飞书只返回“内部错误”，请先核对 App ID。

### 2.2 事件地址（7 步）

1. **准备公网事件地址。** 飞书只能把事件发到公网可以访问的 HTTPS 地址。
2. **在飞书开放平台创建应用**，同上；另外在“事件与回调 → 加密策略”中记下 Verification Token。Encrypt Key 保持为空：witden 不接收加密推送的事件。
3. **填写凭据并测试连接。** 填写 App ID、App Secret 和 Verification Token。
4. **订阅消息事件。** 在“事件与回调 → 事件配置”中把订阅方式设为“将事件发送至开发者服务器”，请求地址填页面显示的事件地址并保存。飞书会立即验证这个地址，页面显示验证结果；Verification Token 不对时会说明并可以回到上一步修改。然后添加事件 **接收消息 v2.0**（`im.message.receive_v1`）。
5. 至 7. 与长连接的第 4 至 6 步相同。

### 2.3 需要的权限

下表是每个接入都需要的基础权限。引导中给出权限列表的 JSON，在飞书开发者后台的“权限管理”中点击“批量导入/导出”，粘贴后点击“申请开通”即可一次申请全部权限；也可以按权限标识逐项搜索开通。引导中还可以勾选扩展（飞书工具，见第 4 节），JSON 会一并包含。下面的 JSON 只含基础权限。

```json
{
  "scopes": {
    "tenant": [
      "im:message.group_at_msg:readonly",
      "im:message.p2p_msg:readonly",
      "im:message:send_as_bot",
      "im:chat:readonly",
      "contact:contact.base:readonly",
      "contact:user.base:readonly",
      "im:message.group_msg.include_bot:read"
    ],
    "user": []
  }
}
```

| 权限 | 名称 | 用途 |
|---|---|---|
| `im:message.group_at_msg:readonly` | 接收群聊中@机器人消息事件 | 收到群里 @ 机器人的消息 |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 | 收到发给机器人的私聊消息 |
| `im:message:send_as_bot` | 以应用的身份发消息 | 发送角色的回复 |
| `im:chat:readonly` | 获取群组信息 | 读取群名和群成员（包括名字），判断回复会被谁看到 |
| `contact:contact.base:readonly` | 获取通讯录基本信息 | 与下一项一起，在私聊中显示对方的名字 |
| `contact:user.base:readonly` | 获取用户基本信息 | 与上一项一起，在私聊中显示对方的名字 |
| `im:message.group_msg.include_bot:read` | 获取群组中用户和机器人发送的消息 | 群里没有 @ 机器人的消息，包括其他机器人发的，也记入话题，作为角色的上下文，但不交给角色 |

- 还要在“权限管理 → 数据权限”中把通讯录权限范围设为会使用机器人的成员（例如全部成员）。witden 只读取人的名字；不设置时私聊中显示对方的 ID，群聊中的名字不受影响（从群成员列表读取）。
- 是否需要审核以申请时页面上的标注为准，企业管理员可以调整。版本中有需要审核的权限时，整个版本要等企业管理员在飞书管理后台通过后才生效；不想等的话，可以先删掉那一项，以后再申请并发布新版本。
- 其他机器人发在群里的消息记入话题，在 witden 中显示为一个外部成员（名字在有人 @ 它之前显示为“机器人”加 ID 末尾 6 位）。默认只作为上下文，即使 @ 了这个机器人也不交给角色，以免机器人之间互相触发。需要时，在接入的“编辑”或设置引导的“选择机器人代表的角色”一步中开启“其他机器人 @ 这个机器人时，也交给角色处理”：开启后这类消息也交给角色；连续 8 次（部署配置项 `WITDEN_MAX_AUTO_ROUNDS`）都是机器人的请求、中间没有人发言时，之后的只记录（“收到的事件”中显示“机器人连续请求已达上限”），等有人发言再继续。机器人自己发出的消息不会重复记录。
- 权限和数据权限都在发布版本后生效。已经接入的应用新增权限后，也要发布一个新版本。

### 2.4 切换方式

使用事件地址的接入，详情页会显示“改用长连接”按钮，点击后打开切换引导：沿用原来的飞书应用，不需要重新创建，群聊、私聊、机器人代表的角色和已关联的账号都保持不变。在引导中确认改用长连接后，witden 删除保存的 Verification Token 并连接飞书；再到飞书开发者后台把订阅方式改为“使用长连接接收事件”，按需发布新版本。在飞书中改好之前，消息仍推送到事件地址，witden 会拒收并在详情页说明原因。

也可以在引导开头选择另一种方式，或在接入详情中点击“编辑”修改“接入方式”。改用事件地址时需要填写 Verification Token，并在飞书中改回“将事件发送至开发者服务器”。

## 3. 选择角色与关联身份

- 一个飞书应用就是一个机器人，代表 witden 中的一个角色：群里 @ 它的消息和发给它的私聊消息都交给这个角色处理。需要多个角色时，为每个角色各建一个飞书应用（在 witden 中各是一个接入）。没有选择角色的接入不接收请求。
- witden 按飞书用户的 open_id 识别用户，名字只用于显示：群里的人取群成员列表中的名字，私聊对象需要 2.3 节中的通讯录权限和通讯录权限范围，否则显示为 `feishu-<open_id>`，知道名字后自动改过来。显示的是飞书接口返回的、成员在企业通讯录中的姓名，例如飞书返回“用户”加一串数字时，witden 也照样显示。在飞书中改了姓名后，witden 会跟着改（最长约一小时，在下一条消息时生效）；在 witden 中改过名字的外部成员不受影响。在“设置 → 通讯接入 → 身份关联”中，把管理员自己的飞书账号关联到 witden 管理员账号；其他人按接入的外部成员设置处理。

## 4. 飞书工具

角色可以经 witden 使用一家公司飞书中的日历、文档与知识库、多维表格、电子表格、视频会议和任务。飞书应用的凭据只保存在平台中，角色和虚拟电脑都拿不到：每次调用由平台用这个接入的应用身份完成，角色只看到结果。

### 4.1 为应用申请扩展权限

设置引导第 1 步在基础权限之外列出扩展（飞书工具），按需勾选，权限列表 JSON 随之更新，一并批量导入申请。已经接入的应用，在接入详情的“飞书应用的权限”中点击“申请更多权限”，同样勾选后复制 JSON。

| 扩展 | 申请的权限 | 角色可以做的事 |
|---|---|---|
| 日历 | `calendar:calendar` | 查看日历、日程和某人的忙闲；创建日程并邀请参与人 |
| 文档与知识库 | `docx:document`、`drive:drive`、`wiki:wiki` | 读取文档、云空间文件夹和知识库；新建文档、追加内容 |
| 多维表格 | `bitable:app` | 查看数据表、字段和记录；新增、修改记录 |
| 电子表格 | `sheets:spreadsheet` | 读取、写入单元格区域 |
| 视频会议 | `vc:reserve` | 预约会议，得到入会链接 |
| 任务 | `task:task:write` | 创建任务，设置截止时间和负责人 |

接入详情的“飞书应用的权限”会向飞书查询这个应用实际开通了哪些权限，列出基础权限中未开通的项，以及每个扩展是可读写、只读还是未开通。在飞书中申请并发布新版本后，点击“重新检测”。

以应用身份访问时，飞书只允许应用接触授权给它的内容：文档、电子表格和多维表格要在其中通过“…→ 更多 → 添加文档应用”把这个应用加进来（写入需要编辑权限）；知识库要把应用加为知识空间成员；日历要共享给应用。应用新建的文档保存在应用自己的云空间里，witden 会把它分享给提问的人（可编辑）。

### 4.2 给角色授权

在“设置 → 角色管理”编辑角色，“权限”中的“飞书工具”按飞书应用（公司）分别列出各项扩展，每项可以选：

- **禁用**：角色不能使用（默认）；
- **只读**：可以查看，不能创建或修改；
- **读写，写入需询问**：查看直接进行，创建或修改前由有审批权限的人批准；
- **读写**：查看、创建和修改都直接进行。

每个飞书应用单独设置，允许了一家公司的日历，不等于允许另一家公司的。飞书应用还没有开通的扩展，会在旁边注明“飞书应用未开通”或“只开通了只读”。删除飞书接入时，各角色对这个应用的授权一并删除。

- 角色同时能用几家公司的飞书时，要指明用哪一家；角色可以先查看自己能用哪些飞书应用，以及 witden 认识的这家公司的人（用来邀请参会人、指派任务）。
- 预约视频会议时，会议的主持人是提问的人在这家公司飞书中的账号；提问的人没有关联这家公司的飞书账号时不能预约。
- 从飞书读到的内容视为这家公司飞书内可见：发回这家公司的飞书会话和控制台不受限制，发到别的公司、Slack 或 GitHub 之前，需要管理员批准（见[使用指南](user-guide.md#5-审批与资料保护)）。
- 写入飞书（新建日程、文档、记录等）之前，witden 检查写入的内容会被谁看到：写进一家公司的飞书，就是这家公司的人能看到。如果角色在这项工作中读过他们看不到的资料（例如另一家公司的飞书文档、私有 GitHub 仓库、其他私信或话题），写入会先暂扣，由资料的所有者在控制台批准；在控制台里提出请求时，这个话题本身的内容不需要批准。
- 飞书拒绝调用时，结果会说明原因，例如应用没有开通所需的权限，或没有被添加到这个文档。

## 5. 已知限制

- 文件、图片、消息的编辑和撤回不同步。
- 没有开通 `im:message.group_msg.include_bot:read` 时，群聊话题中只有 @ 机器人的消息和角色的回复。
- 文字、富文本（标题和段落，图片显示为“[图片]”）和卡片中的文字会被记录；图片、文件、语音等其他消息不同步。
- 事件地址方式不支持加密推送（Encrypt Key）。
- 不支持 Lark 国际版。
