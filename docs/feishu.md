# 接入飞书（实验性）

接入后，角色可以作为机器人在飞书中工作：在群里 @ 机器人或私聊它，就能把工作交给 witden 中的角色。群里的一条消息连同它的回复（消息串）对应 witden 中的一个会话，角色在同一个消息串中回复；与机器人的私聊是一个会话。飞书接入目前为实验性，只同步文字消息，不同步文件、消息的编辑和撤回。

配置需要 witden 管理员账号，以及飞书企业的应用开发权限（发布应用时可能需要企业管理员审核）。飞书把消息推送到 witden 的公网事件地址（只通往事件端口，不开放控制台），准备方法见[部署与配置](deployment.md#24-公网事件地址)。witden 目前只支持飞书（open.feishu.cn），不支持 Lark 国际版。

## 1. 用设置引导接入

在“设置 → 通讯接入”中点击“新建接入”，选择 **飞书**，按页面中的 7 步完成。中途离开后，可以在接入详情中点击“设置引导”继续。

1. **准备公网事件地址。** 飞书只能把事件发到公网可以访问的 HTTPS 地址。
2. **在飞书开放平台创建应用。** 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用（名称就是机器人在飞书中显示的名字），在“添加应用能力”中添加 **机器人**，在“权限管理”中开通下表的权限，并在“事件与回调 → 加密策略”中记下 Verification Token。Encrypt Key 保持为空：witden 目前不接收加密推送的事件。
3. **填写凭据并测试连接。** 填写 App ID（`cli_` 开头）、App Secret（都在“凭证与基础信息”页面）和 Verification Token。witden 加密保存它们，之后不能再查看。测试会读取机器人的信息；应用发布之前飞书不提供机器人信息，这时页面会说明原因，可以先继续下一步。
4. **订阅消息事件。** 在“事件与回调 → 事件配置”中把订阅方式设为“将事件发送至开发者服务器”，请求地址填页面显示的事件地址并保存。飞书会立即验证这个地址，页面显示验证结果；Verification Token 不对时会说明并可以回到上一步修改。然后添加事件 **接收消息 v2.0**（`im.message.receive_v1`）。
5. **发布应用版本。** 在“版本管理与发布”中创建版本，在可用范围中选择能使用机器人的成员或部门，申请线上发布；需要审核时等企业管理员通过。开通的权限、机器人能力和事件订阅在发布后才生效，之后每次修改也要再发布一个新版本。发布后在这一步测试连接。
6. **选择机器人代表的角色**，以及是否允许未关联的人使用，见[接入 Slack](slack.md#3-选择机器人代表的角色)。
7. **在飞书中试一试。** 在群设置的“群机器人”中添加这个应用，在群里 @ 机器人，或直接私聊它；页面显示 witden 收到的消息和处理结果。

| 权限 | 名称 | 用途 |
|---|---|---|
| `im:message.group_at_msg:readonly` | 接收群聊中@机器人消息事件 | 收到群里 @ 机器人的消息 |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 | 收到发给机器人的私聊消息 |
| `im:message:send_as_bot` | 以应用的身份发消息 | 发送角色的回复 |
| `im:chat:readonly` | 获取群组信息 | 读取群成员，判断回复会被谁看到 |

## 2. 选择角色与关联身份

- 一个飞书应用就是一个机器人，代表 witden 中的一个角色：群里 @ 它的消息和发给它的私聊消息都交给这个角色处理。需要多个角色时，为每个角色各建一个飞书应用（在 witden 中各是一个接入）。没有选择角色的接入不接收请求。
- witden 按飞书用户的 open_id 识别用户。在“设置 → 通讯接入 → 身份关联”中，把管理员自己的飞书账号关联到 witden 管理员账号；其他人按接入的外部成员设置处理。

## 3. 已知限制

- 只同步文字消息；文件、图片、消息的编辑和撤回不同步。
- 不支持加密推送（Encrypt Key）和长连接方式接收事件。
- 不支持 Lark 国际版。
