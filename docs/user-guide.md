# 使用指南

本指南面向 witden 的管理员（能登录控制台的账号都是管理员），介绍如何在控制台中与 AI 角色协作、查看角色在各处的会话、查看和接管虚拟电脑，以及如何配置角色和处理审批。部署方法见[部署与配置](deployment.md)。

## 1. 界面概览

平台中除内置的系统管理员外还没有其他角色时，第一次登录会打开“欢迎使用 witden”引导：连接模型服务、选择模型后，witden 自动准备一台桌面虚拟电脑和一个助手（@assistant），内置的系统管理员（@admin，见 4.3）还没有模型时也使用这个模型。如果模型不能调用工具或理解图片，引导会提示：前者角色只能对话，后者助手看不到桌面截图。也可以点击“跳过，自己配置”，按[部署与配置](deployment.md#3-首次配置)中的步骤手动配置。

左侧边栏包含：

- **任务**：全部任务。
- **审批**：等待处理的审批请求。
- **话题**：控制台里的话题，按最近活动排序；有新消息的话题加粗显示。点击右侧的“+”新建话题，点击“话题”标题查看全部会话。
- **角色**：全部启用的角色。点击角色即打开你与它的私信；鼠标悬停会出现编辑按钮。
- **各个通讯接入**：每个 Slack 工作区、飞书应用、GitHub 账号一组，列出角色在那里的会话：`#` 为频道（一个频道一个会话，thread 中的消息显示为回复），`@` 为私信，`◎` 为 issue，`⇄` 为 pull request。
- **设置**：虚拟电脑、角色管理、模型、通讯接入和系统管理。

侧边栏宽度可以拖动调整，双击分隔线恢复默认宽度。

**未保存的修改**：设置表单（角色、模型、虚拟电脑模板与资源限制、模型访问、通讯接入与 Slack 应用、接入引导中的角色选择、账号、话题设置、话题调度、公网地址）有改动但还没保存时，离开不会直接丢掉修改：

- 在控制台内去别的页面，包括点击侧边栏、浏览器的后退和前进、切换“系统管理”的标签，会询问“保存并离开”“不保存，离开”或“继续编辑”。选择保存但没有保存成功时（例如必填项为空），会留在原处并提示。
- 切换同一页面中会关闭表单的位置也会询问，例如话题右侧栏的标签、虚拟电脑详情的标签、通讯接入列表中的另一项。
- 刷新或关闭浏览器标签页时，显示浏览器自己的确认框（浏览器不允许网页自定义这个提示的文字）。

点击表单中的“取消”或关闭对话框，视为放弃修改，不再询问。

点击侧边栏的“话题”标题打开**全部会话**：列出角色参与的全部会话（控制台、Slack、飞书、GitHub），可以按来源筛选、搜索，或包含已归档的会话。来自外部的会话顶部会显示它所在的位置，例如“GitHub · acme/api #12”，并提供在原平台中打开的链接；关于各平台的接入，见[接入 Slack](slack.md)和[接入 GitHub](github.md)。

## 2. 在话题中协作

### 2.1 创建话题

在“话题”旁点击“+”，填写：

- **标题**和**目标**：目标会作为角色在这个话题中工作的背景，建议写清楚要完成什么。
- **邀请成员**（其他管理员）和**邀请角色**。

所有管理员都能查看全部话题和私信；参与话题的人才能发言，不是参与者时可以在右侧“参与者”中把自己加入。参与者（管理员和角色）可以阅读全部历史，包括自己加入之前的消息。

### 2.2 发送消息

- 输入框支持 Markdown：标题、列表、表格、任务列表、代码块和链接；` ```mermaid ` 代码块会显示为流程图。
- 点击“附件”可以从你自己的电脑上传文件；图片附件直接在消息中显示，点击可放大。
- 消息中写的外部图片地址（例如 `![图](https://…)`）不会自动加载，显示为“外部图片”链接，点击后在新窗口打开；平台中的文件和图片附件照常直接显示。
- 按 Enter 发送，Shift+Enter 换行。

你发送的消息显示在右侧，角色和其他成员的消息按发送者显示。

### 2.3 @ 角色和成员

在输入框中输入 @，从弹出的列表中选择角色或成员，才构成一次有效的 @。粘贴或手动输入的“@名称”只是普通文字，不会让角色开始工作。消息中只有有效的 @ 会高亮显示。

### 2.4 角色响应方式

每个群组话题都可以在顶部的“角色响应”开关中选择以下两种方式之一（鼠标悬停可以查看说明）。只有话题负责人可以切换，也可以在右侧栏“设置”中修改。

| 方式 | 说明 |
|---|---|
| 主动 @（默认） | 角色只在被 @ 时响应。 |
| 自动 | 没有 @ 任何角色的消息也可能交给角色处理。话题中只有一个角色时，它会查看每条消息并自行判断是否需要回复，例如成员之间闲聊时不回复。话题中有多个角色时，由管理员配置的调度模型决定交给哪些角色，可以是一个、多个或都不交。 |

在两种方式下，被 @ 的角色都会响应。私信中的角色总是回复你的消息。

如果话题设为“自动”且有多个角色，但管理员尚未配置调度模型，话题顶部会显示“未设置调度模型”，此时没有 @ 的消息不会交给任何角色。

### 2.5 查看角色的工作

- 角色接到工作后，消息区底部会显示它的状态：“正在思考”、正在使用的工具（例如“正在执行命令”），以及正在生成的回答。如果回答涉及当前话题中部分成员无权查看的资料，只显示状态而不显示内容。
- 右侧栏“任务”列出话题中的全部任务。对进行中的任务，你可以**暂停**、**补充要求**、**转交**给其他角色或**取消**；失败或已取消的任务可以**重试**。
- 点击任务标题可以查看每一步的执行记录和分配依据。

### 2.6 右侧栏

话题和私信的右侧栏大体相同，区别见 2.7。

| 标签 | 内容 |
|---|---|
| 任务 | 话题中的任务及其控制操作。 |
| 审批 | 话题中等待处理的审批。 |
| 虚拟电脑 | 话题中角色所在的虚拟电脑，见第 3 节。 |
| 参与者 | 管理员和角色列表，可以邀请或移除。 |
| 文件 | 话题中的全部文件，点击下载到你自己的电脑。 |
| 记忆 | 本话题的记忆，角色在这个话题中工作时会参考。 |
| 设置 | 标题、目标、角色响应方式、角色之间自动讨论的轮次上限；归档、发布到外部频道和清理数据。 |

### 2.7 私信

点击侧边栏中的角色即可与它私信。私信是你与这个角色之间一直保留的一对一对话，其中的资料不会被带到其他话题，除非你批准。

私信与话题的区别：

| | 话题 | 私信 |
|---|---|---|
| 参与者 | 多位管理员和多个角色，可以邀请和移除 | 只有你和一个角色，不能邀请或移除；其他管理员可以查看，但不能发言 |
| 让角色工作 | 按话题的响应方式，通常需要 @ 角色 | 不需要 @，每条消息都交给这个角色 |
| 设置 | 标题、目标、响应方式、讨论轮次上限 | 无需设置 |
| 结束 | 事情完成后可以归档，归档后只读 | 不归档，一直保留；可以在“设置”中清空记录 |
| 右侧栏 | “参与者”列出管理员和角色 | “角色”显示这个角色的职责、所在的虚拟电脑和模型 |
| 角色停用后 | 角色不再响应，话题照常使用 | 角色从侧边栏消失，私信变为只读，可在“全部话题”中查看；角色重新启用后恢复 |

需要多人或多个角色一起处理的事情，请新建话题并邀请他们。

每个角色在各个话题和私信中的会话记录（已交付结论的摘要）可以在“角色管理”中该角色的页面查看；任务详情中也会显示任务所属的会话。

## 3. 虚拟电脑

### 3.1 在话题中查看

右侧栏“虚拟电脑”标签显示话题中角色所在的虚拟电脑。有多台时可以在顶部切换。顶部一行显示虚拟电脑名称、运行状态和当前操作者（空闲、AI 操作中或某位成员正在接管）。

- **桌面虚拟电脑**：显示只读的实时画面缩略图。鼠标悬停在缩略图上会出现放大图标，点击即可放大。
- **命令行虚拟电脑**：管理员可以在这里直接执行命令。

点击“放大”后，虚拟电脑画面占据整个话题区域，对话收起为右下角的“对话”按钮，有新消息时按钮上会显示数量。点击按钮打开对话窗口，拖动窗口标题栏可以移动它，拖动边缘或角可以调整大小；对话按钮本身也可以拖动。点击“还原”恢复正常布局。

### 3.2 接管与交还

需要亲自操作时（例如完成登录或验证码），管理员可以在放大后的画面中点击状态栏上的“接管并操作”：

- 接管后，你的鼠标和键盘操作会发送到这台虚拟电脑，不会影响你自己的电脑；这台虚拟电脑上所有角色的 AI 工作暂停。
- 如果当时有 AI 工作正在进行，会先提示将暂停几项工作，确认后接管。
- 完成后点击“交还控制”，AI 工作随即恢复。

为避免 AI 工作长时间停滞，出现以下情况时系统会自动交还控制：

- 离开当前页面或视图，例如切换到其他页面、切换右侧栏标签、还原布局或关闭页面；
- 浏览器标签页在后台停留超过 30 秒；
- 超过 5 分钟没有鼠标或键盘操作；
- 浏览器异常关闭或网络中断时，服务器在约 3 分钟后自动交还。

### 3.3 虚拟电脑页面

在“设置 → 虚拟电脑”中可以查看和管理全部虚拟电脑。每台虚拟电脑的页面包括：

| 标签 | 内容 |
|---|---|
| 概览 | 状态、资源占用、分配的角色、共享范围；启动、停止、重启、重置、删除等操作。 |
| 屏幕 | 实时画面（桌面虚拟电脑）与截图。 |
| 控制台 | 以虚拟电脑内的普通用户身份执行命令，所有命令记录审计。 |
| 会话 | 角色打开的终端和浏览器会话。 |
| 模型访问 | 允许虚拟电脑中的程序使用平台的模型，见 3.4。 |
| 备份与复制 | 备份、恢复，以及复制为新的虚拟电脑（默认不复制账号凭据）。 |
| 任务 | 在这台虚拟电脑上执行过的任务。 |

同一台虚拟电脑上的角色共享文件、已安装的软件和登录状态。需要互相保密的工作，请分配到不同的虚拟电脑。

### 3.4 虚拟电脑内的模型访问

在“模型访问”中开启后，虚拟电脑中的程序（例如管理员或角色安装的其他工具）可以通过虚拟电脑内部的地址，使用平台为这台虚拟电脑签发的密钥调用平台中的模型。页面会显示 OpenAI 兼容、Anthropic 和 System One（用于 Jev、Laya 等 System 1 模型，见 8.1）三种接口的地址，这些地址只在这台虚拟电脑内部有效。真实的服务地址和密钥不会进入虚拟电脑；签发的密钥不在控制台中显示，由执行代理写入虚拟电脑中的环境变量文件供程序使用；它可以随时更换，离开这台虚拟电脑无法使用。只能选择你自己有权使用的模型，用量按虚拟电脑统计。

## 4. 角色

在“设置 → 角色管理”中创建和编辑角色。

| 部分 | 内容 |
|---|---|
| 身份 | 名称、@ 名称（在话题中用于 @）、头像（从自己的电脑上传 PNG、JPEG、GIF 或 WebP 图片，最大 1 MB）、徽章颜色、职责说明。 |
| 工作方式 | 提示词：职责、工作规则和沟通方式，以及需要角色长期记住的岗位知识（例如“发布前必须跑完 make check”）。权限由系统执行，不依赖提示词。 |
| 模型 | 角色使用的模型、模型能力、思考程度（effort）和模型参数。 |
| 虚拟电脑 | 角色工作所在的虚拟电脑。未分配时角色只能对话（系统管理员不需要虚拟电脑，见 4.3）。 |
| 权限 | 工具权限、可以联系和委托的角色、可读取的知识空间。 |
| 限额 | 单个任务的最大步数和 token 上限、每日 token 上限。 |

**思考程度（effort）**决定模型回答前思考得多充分：等级越高，思考越充分，用时和 token 也越多；选“默认”由模型自己决定。可选的等级取决于模型：

- **模型服务报告的等级**：在“设置 → 模型”中对模型点击“检测能力”时，witden 会向模型服务查询这个模型支持哪些等级。Anthropic、DeepSeek、OpenRouter 等服务会报告，查到后模型列表中显示“思考程度：……”，角色设置中只列出这些等级。
- **witden 已知的模型**：服务不报告、但文档写明了等级的模型（例如 OpenAI 的部分模型），witden 内置了一张表，按模型名称匹配，直接列出这些等级。
- **常见等级**：以上都没有时（例如多数自部署服务），列出常见等级（none、minimal、low、medium、high、xhigh、max；Anthropic 接口为 low 到 max），模型不支持所选等级时，请求会出错。
- witden 按服务的要求发送：Anthropic 接口放在 `output_config.effort`，OpenRouter 类服务放在 `reasoning.effort`，其他 OpenAI 兼容接口（包括 DeepSeek）使用 `reasoning_effort`。
- DeepSeek 等服务会返回模型的思考内容，并要求之后的请求把它带回；witden 会保存并在下一轮请求中带回，只对返回了思考内容的服务这样做。

添加模型服务的界面在“设置 → 模型”和首次使用引导中是同一套：选择常见服务（OpenAI、Anthropic、DeepSeek、通义千问、Kimi、智谱、OpenRouter，以及调度用的 TypeSafe Jev、Laya）会自动填好地址和协议，只需填写 API Key；“其他服务”可以自己选择协议和地址。添加后在“添加模型”中从服务的模型列表选择，或填写模型名称。

角色设置中的“模型参数”（例如 `{"temperature": 0.2}`）与模型自身的参数合并后随每个请求发送，角色的设置优先。

### 4.1 工具权限

工具按类别列出，每一类可以设为：

- **始终允许**：直接使用；
- **询问**：每次使用前需要管理员批准，角色不能批准自己的请求；
- **禁用**：角色不能使用。

展开某一类可以单独要求其中的某个工具“询问”。

无论权限如何设置，角色都可以在当前话题中发消息（可以针对一个请求连续发几条）、查阅和搜索当前话题的消息、向人提问和更新进度。

新建角色的默认权限为：在自己虚拟电脑里的操作（执行命令、终端、文件、桌面、浏览器，以及把虚拟电脑中的文件分享到话题）始终允许；联系或委托其他角色、使用平台记忆、读取其他话题、修改自己的职责说明需要询问。已有角色可以在权限列表底部点击“恢复默认”套用默认值。

**职责说明**这一类只有一个工具：角色可以修改自己的职责说明（别人邀请、私信时看到的介绍），例如你告诉它“以后你负责前端，更新一下你的职责说明”。它只能改职责说明这一项，不能改提示词、模型、权限等其他设置，也不能改其他角色。这个工具只在控制台的话题和私信中提供，在 Slack、飞书、GitHub 的会话中没有；默认为“询问”，批准时可以看到新的职责说明全文。职责说明对所有人可见，角色读过当前话题中部分人无权查看的资料时不能修改。系统管理员默认没有这个工具。

**飞书工具**：接入了飞书时，权限中还有“飞书工具”，按飞书应用（公司）分别设置日历、文档与知识库、多维表格、电子表格、视频会议、任务，每项可选禁用、只读、读写（写入需询问）或读写。角色经 witden 调用飞书，拿不到飞书应用的凭据；从飞书读到的内容视为该公司飞书内可见。详见[接入飞书](feishu.md#4-飞书工具)。

无论工具权限如何设置，内容发往 Slack、飞书会话之前都会检查其中的资料是否允许那里的人看到，见第 5 节。

### 4.2 修改角色的影响

角色正在进行的任务继续使用开始时的配置，新任务使用新配置。更换角色所在的虚拟电脑不会迁移文件、已安装的软件和登录状态；固定在原虚拟电脑上的任务需要等待完成或取消。

### 4.3 系统管理员

witden 内置一个系统管理员角色（@admin）：平台启动时自动创建，始终存在，只有一个，不能停用、复制，也不能另外添加。它可以像管理员一样读取和修改 witden 的配置，例如“把 @dev 的模型换成 Claude”“新建一台桌面虚拟电脑给 @test 用”“让 Slack 接入允许未关联的人使用”。在私信或控制台话题中向它提出要求即可。

- **可以配置的内容**：角色（系统管理员角色除外）、模型服务和模型、调度模型、虚拟电脑模板和实例（包括启动、停止、备份）、通讯接入的设置（名称、暂停、机器人代表的角色、外部成员、角色身份）、公网事件地址、知识空间与岗位知识；还可以查看用量、审计记录和紧急停止。
- **不管理账号**：控制台账号（新建、停用、密码）和 Slack、飞书、GitHub 账号的身份关联只能由人在“系统管理 → 账号”和“通讯接入 → 身份关联”中操作，它也读不到账号列表。
- **以提问人的身份操作**：每次修改都和这位管理员在控制台中操作一样经过检查，审计记录中写明由哪个系统管理员角色在哪个任务中完成。它的提示中要求重置、删除等难以撤销的操作先向你确认；需要由系统保证时，见本节最后一条。
- **读不到也改不了密钥**：模型 API Key、通讯接入凭据、Tunnel token、密码都只能由人在控制台中填写；需要时它会告诉你到哪里填写。不要把密钥发到对话中。
- **只在控制台中工作**：它不能作为 Slack、飞书、GitHub 机器人代表的角色，在与外部会话关联的话题中不工作，其他角色也不能联系或委托它。
- **不需要虚拟电脑**：它的工具作用于 witden 本身；分配了虚拟电脑时，也可以使用其中的工具。
- **它的设置由人修改**：在“设置 → 角色管理”中可以修改它的名称、头像、提示词、模型、工具权限和限额，它自己不能修改。平台创建它时使用多数角色正在用的模型；还没有模型时，首次使用引导会让它使用你选择的模型。默认只开启“witden 配置”工具，并且不需要询问；如果希望每次修改前都由人批准，把“修改 witden 配置”设为“询问”。

## 5. 审批与资料保护

以下情况会产生审批，出现在“审批”页面和话题右侧栏中：

- **工具审批**：角色使用设为“询问”的工具。任何管理员都可以审批。
- **资料公开审批**：角色要发往 Slack、飞书会话的内容，用到了那里的人无权查看的资料，例如某位管理员与角色的私信，或另一位 Slack 用户的私信。这类内容会先暂扣，由资料来源的管理员（例如私信的主人）决定是否公开；资料只来自外部的人时，由任一管理员决定。一次批准只放行一条消息。

控制台内部的话题和私信之间不需要这类审批：所有管理员都能看到全部会话。

## 6. 账号与外部成员

**管理员**：能登录控制台的账号都是管理员，可以配置角色、虚拟电脑、模型和通讯接入，查看全部会话和任务，处理审批。在“设置 → 系统管理 → 账号”中添加或停用管理员账号。

**角色在 Slack、飞书中服务的人**：

- 关联到管理员账号的 Slack、飞书用户（在“通讯接入 → 身份关联”中设置），在那里发出的请求视为这位管理员的请求。
- 未关联的人：通讯接入开启“允许未关联的人使用”后，他们第一次与机器人对话时自动成为这个接入的**外部成员**，在“账号”列表中标为“外部成员”。外部成员只能使用接入的机器人代表的角色，不能登录控制台；每个人与机器人的私信相互隔离。未开启时，他们会收到账号未关联的提示。详见[接入 Slack](slack.md)。

资料保护面向外部：内容发往 Slack、飞书会话之前，平台会检查其中的资料是否允许那里的人看到，见第 5 节。

## 7. 紧急停止

在“设置 → 系统管理 → 紧急停止”中可以立即暂停全部 AI 执行，或只暂停某个角色、某台虚拟电脑、某个通讯接入、某个话题或某项任务（包括它委托出去的工作）。停止期间做出的审批决定会被记录，解除后才执行。解除后，被暂停的任务可以继续。

## 8. 话题调度

“设置 → 系统管理 → 话题调度”用于选择调度模型（需要“管理模型与密钥”权限）。当话题设为“自动”且有多个角色时，调度模型判断没有 @ 角色的消息应交给哪些角色。调度的 token 用量计入所选模型。

### 8.1 System 1 模型

调度模型必须是 **System 1 模型**。System 1 模型不生成文字，而是针对给定内容回答选择、是/否、打分等问题，并给出每个答案的概率，一次判断通常只需几十到几百毫秒。它们使用 System One 接口（`POST {地址}/v1/systemone`），与 OpenAI、Anthropic 的对话接口不同，因此只能用于话题调度和虚拟电脑内的模型访问（见 3.4），不能用作角色的模型。

目前支持以下两种：

| 模型 | 说明 | API 地址 | API 密钥 | 模型名称 |
|---|---|---|---|---|
| TypeSafe Jev | 托管服务，也可以通过 OpenRouter 使用 | `https://api.typesafe.ai`；通过 OpenRouter 时为 `https://openrouter.ai/api` | TypeSafe 或 OpenRouter 的密钥 | 一般为 `jev-latest`，可以从接口获取列表；OpenRouter 上为 `typesafe/jev-1.13` 等 |
| Laya | 开源（Apache-2.0），自行部署。Docker Compose 部署可以直接启用随附的 `laya` 服务，平台会自动添加，见[部署与配置](deployment.md#23-可选laya-调度模型)；也可以 `pip install "laya[serve]"` 后运行 `laya-serve`，默认端口 8000 | `http://<主机>:8000` | 部署时设置的 `LAYA_API_KEY`；未设置时留空 | 需要手动填写：中文对话用 `multilingual`，纯英文可用 `english` |

Laya 对中文对话的判断明显弱于 Jev：在 Laya 项目公开的中文办公对话测试（64 例）中，Laya 多语言模型判断正确 20 例，Jev 全部正确。对调度准确度要求较高时，建议使用 Jev。

### 8.2 配置步骤

1. 在“设置 → 模型”中点击“添加服务商”，选择“TypeSafe Jev”或“Laya”，填写 API 地址和密钥。
2. 添加模型：在“添加模型”中，Jev 可以从模型列表中选择，也可以填写名称；Laya 服务不提供模型列表，请填写模型名称。
3. 点击“检测能力”。平台会提一个答案明确的问题，检测连接、回答是否正确以及响应时间。
4. 回到“话题调度”，选择该模型并保存。列表只显示 System 1 模型。

### 8.3 调度方式

调度模型只看这条消息本身及其发送人，在“各个角色”（依据角色的名称和职责说明）与“不需要角色”之间选出最可能的一项：

- 选中某个角色时，这个角色接手；概率不低于 30% 的其他角色也一起接手。
- 选中“不需要角色”时（例如闲聊、感谢、成员之间的对话），消息不交给任何角色。
- 接手的角色仍可以判断不需要回复。每项任务的分配记录中会显示调度时各选项的概率。

调度模型不参考之前的对话。回答某个角色的提问时（例如“好的，继续”），请 @ 这个角色。

调度模型被停用、服务不可用，或者不是 System 1 模型时（例如之前选择的是对话模型），没有 @ 的消息不会交给角色，话题中会给出提示。

点击侧边栏左下角你的名字进入个人页面，可以查看账号信息，以及角色为你保存的私密记忆（可以删除）。
