# 安全说明与部署建议

“使用 Docker” 本身不等于安全。下面写清楚 witden 做了什么、依赖什么、还需要部署方做什么。

## 平台保证的事情

| 要求 | 实现 |
|---|---|
| AI 操作只发生在所属虚拟电脑 | 所有 AI 工具经过执行网关，只认任务固定的实例；没有宿主机执行路径；虚拟电脑不可用时等待或失败。 |
| AI 拿不到宿主机/容器管理权限 | 只有 Docker Manager 持有 Docker；API 只能请求它做白名单内的操作，Worker 完全没有 Docker 权限。虚拟电脑容器不挂 Docker socket、只挂平台管理的命名卷、`cap_drop=ALL`、`no-new-privileges`、禁止特权与 host 网络。 |
| 虚拟电脑内非 root | 模板和 Manager 双重拒绝 root 用户（名称、uid 或 gid 为 0）；Runner 自己也拒绝以 root 运行。 |
| Runner 不可冒充 | 每台虚拟电脑的 Runner 令牌在每次创建容器时重新签发，数据库只存哈希；拨入 Hub 时校验实例 ID 与令牌，失败会被审计。Runner 启动的进程看不到令牌。 |
| 断线不重复操作 | 有副作用的操作结果不确定时，先查询 Runner 的请求日志；查不到就告诉模型“不确定”，不会自动重做。 |
| 角色复制环境不带凭据 | 克隆时剔除模板声明的凭据路径（`~/.ssh`、浏览器配置、`~/.aws` 等），并清理镜像层中的同名路径；连同凭据复制需要 `secrets.manage`。 |
| 密钥不外泄 | 模型密钥与通讯凭据以主密钥加密（AES-256-GCM）存储，接口从不返回；日志、审计、工具输出做脱敏。 |
| 虚拟电脑内的模型访问不泄露真实密钥 | 可选的模型代理只把虚拟电脑内部的地址和平台为这台虚拟电脑签发的密钥放进虚拟电脑；请求经 Runner 的已认证连接回到平台，平台核对密钥和允许的模型后用真实密钥转发。签发的密钥离开这台虚拟电脑无效，可随时更换或关闭；只有自己有权使用某个模型的人才能把它开放给虚拟电脑。 |
| 权限不靠提示词 | 工具可用性、可联系角色、输出受众、审批都由服务端检查；提示词只是说明。 |
| 失败即关闭 | 未知标签、成员未知或超过 30 分钟未刷新的私有会话、无匹配规则的外部会话一律按最严格处理。 |
| 间接通道同样受控 | 实时事件按事件重新鉴权并在事务提交后才推送；任务日志、标题、等待信息、审计详情、进度、文件、话题笔记对读不到其来源的人隐藏或拒绝；入站队列处理完即清空正文，列表不展示正文。 |
| 看得到才能批准 | 审批人必须能读取请求所依据的全部资料；资料公开审批一次只放行一条消息。 |
| 管理员不读私密内容 | 管理员可归档、移除成员、停止工作、清理私密话题，但不能读取或扩大其可见范围；`user.manage` 不能修改管理员账号。 |
| 紧急停止不可绕过 | 停止期间的审批只记录决定，恢复后才执行；按任务停止覆盖整条委托链。 |

## 部署方需要做的事情

1. **保护 Docker Manager。** 它等同于宿主机管理权限：只放在内部网络（compose 中的 `control` 网络），设置足够长的 `WITDEN_MANAGER_TOKEN`；用 `DOCKER_GID` 只把 socket 的组给它。更进一步可使用 rootless Docker，或让 Manager 通过 `DOCKER_HOST` 管理一台专用主机/虚拟机。
2. **Runner Hub 端口。** 虚拟电脑通过宿主机网关访问 :8330。用 `WITDEN_HUB_BIND` 把它绑定到 Docker 网桥地址（如 `172.17.0.1`），不要暴露到公网；Hub 自身要求每台虚拟电脑的令牌。
3. **更强的隔离。** 对处理敏感数据的模板设置 `runtime: runsc`（gVisor）或 Kata，并在 `WITDEN_ALLOWED_RUNTIMES` / `WITDEN_MANAGER_ALLOWED_RUNTIMES` 中启用。
4. **网络。** 虚拟电脑默认在 `witden-computers` 网桥上（虚拟电脑之间关闭互通），可访问外网与宿主机网关。宿主机上的数据库等服务请只监听 `127.0.0.1` 或用防火墙隔离；不需要外网的模板使用 `network: internal` 或 `none`（此时 Runner 走 Manager 的 stdio 通道）。
5. **主密钥与令牌。** 设置 `WITDEN_SECRET_KEY` 并离线备份，丢失后已保存的密钥无法解密；`WITDEN_INTERNAL_TOKEN` 只给 API 和 Worker。
6. **控制台。** 只在内网暴露，前面放 HTTPS 反向代理。
7. **Slack。** 配置 Signing Secret（必需）；按需授予 `chat:write.customize` 以显示角色名称和头像；只把机器人邀请到需要的频道。

## 已知限制

- 同一台虚拟电脑上的角色共享文件、已安装软件与登录状态；互相保密的工作必须分配到不同虚拟电脑。控制台在实例详情中展示共享范围。
- 人或角色在虚拟电脑里安装运行的其他程序（包括别的智能体）拥有这台虚拟电脑上 `witden` 用户的全部能力，平台不逐条审批它们的操作；它们的边界就是虚拟电脑的边界（非 root、无 socket、网络策略）。
- 桌面 Chromium 以 `--no-sandbox` 运行（容器内无 user namespace），依赖容器本身的隔离。
- 资源配额中的磁盘上限依赖存储驱动（overlay2 + xfs pquota）；不支持时会在实例状态中提示“未强制”。
- 记忆检索目前是关键词匹配，不做向量检索。
- 飞书适配器为实验性质（仅文本）；企业微信尚未实现。
